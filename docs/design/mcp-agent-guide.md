# Studio authoring MCP and shared builder

The desktop main process owns the open profile, queue and human draft writer. The MCP server delegates to that owner. It does not launch a second writer or expose the Python worker protocol. Every connection is bound to one recorded job and execution attempt. Ordinary authoring mutations affect only that job's scratch candidates. Explicit grammar-correction jobs receive a separate catalog for checked edits in the selected grammar and automatic reload/regression; see [provider contract](ai-agent-providers.md#explicit-grammar-corrections). They cannot publish source or approve references.

## Install, launch and discover

Use the repository's documented `npm ci`, `npm run doctor`, `npm run build` and `npm start` developer installation. The headless builder compiles the checked-in TypeScript import graph with the installed esbuild dependency; it never compiles text received from an MCP client. The selected local corpus and grammar remain necessary.

`createStudioMcpGateway` is the main-process integration point. `start()` creates a private Unix socket and `<analysis state>/mcp-owner.json`. The socket is inside a mode-0700 temporary directory; socket, discovery and connection files are mode 0600. An existing live owner prevents another gateway from starting for that profile. A stale owner record is replaced only after its PID no longer exists. No TCP listener or browser-accessible unauthenticated endpoint is opened.

`openScope({jobId,attemptId})` issues a short-lived capability and writes a ready-to-use external-client configuration to `<analysis state>/mcp-scopes/<opaque id>.json`. That configuration contains the `mcpServers.studio_authoring` entry:

```json
{
  "command": "<absolute Node or Electron executable>",
  "args": ["<absolute checkout>/electron/studio-mcp-stdio.cjs"],
  "env": {
    "STUDIO_MCP_SOCKET": "<private owner socket>",
    "STUDIO_MCP_TOKEN": "<scoped secret generated by the owner>",
    "ELECTRON_RUN_AS_NODE": "1"
  }
}
```

Use the actual generated values; do not copy these placeholders. Treat the configuration as a temporary credential, not a repository file. The client must launch the command through its MCP configuration. Sending worker-style `{method,params}` lines directly to Python is not an MCP connection.

The shim supports MCP JSON-RPC initialization, paginated `tools/list`, `tools/call`, `resources/list`, `resources/read`, ping and cancellation notifications. The guide is available both as `studio_guide` and `studio://authoring/guide` so clients that omit resources still receive the critical rules. The implementation follows the official [stdio transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) and [tool protocol](https://modelcontextprotocol.io/specification/2025-11-25/server/tools). Supported negotiated protocol versions are 2025-11-25, 2025-06-18, 2025-03-26 and 2024-11-05.

To start an external attempt from the command line, first have a saved passage in the Studio profile, then run:

```sh
node scripts/studio-external-analysis.mjs --passage 'passage:<saved UUID>' --task analyze
```

The command launches or contacts the existing Electron owner, freezes the saved draft/evidence, and prints the scoped configuration path and job identity. `--description` adds an instruction; `--print-config` prints the client configuration itself. No inference request is made by this external attempt. It completes after a candidate proposal or focused question is committed and its MCP success response has been sent. A finite timeout or cancellation preserves scratch work for explicit recovery. The CLI never opens profile state for writing.

Scopes revoke at attempt completion/cancellation; closing the owner makes their socket unavailable. A client cannot extend its own scope, change its job, publish source, approve ground truth or become a profile writer. Connecting to an existing attempt needs no renderer navigation. Job submission and external-attempt initiation remain owner actions, distinct from the scoped authoring tools.

## Tools

All schemas reject unknown fields and bound strings, collections and nesting. Captured project/source/engine values are supplied by the service, never accepted as model overrides.

| Tool                        | Result or action                                                                                                        |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `studio_guide`              | Critical workflow, selected-engine constructor signatures, operation terms/schemas and limits                           |
| `studio_context`            | Immutable input, preserved strings, tentative versus reviewed spelling, frozen preceding context and provenance         |
| `studio_dictionary_search`  | Local website dataset results with offset/limit pagination, separate senses and short definition previews               |
| `studio_dictionary_entry`   | Complete selected definition/examples and exact dataset SHA-256 plus website row index                                  |
| `studio_reuse_search`       | Permitted shared declarations and unnamed source substructures, with origin and index identity                          |
| `studio_reuse_resolve`      | Actual equivalence verification in the destination namespace, including a copied expansion when needed                  |
| `studio_lexicon_inspect`    | Current named predicate/helper inspection; restricted in reconstruction mode                                            |
| `studio_candidate_create`   | Empty, explicit raw, copied candidate or permitted submitted-analysis branch                                            |
| `studio_candidate_get`      | Current scratch source, tree, evaluation and loose pieces; lazy `source`, `nodes`, `evaluation` views                   |
| `studio_candidate_edit`     | One shared builder transaction, guarded by expected candidate revision and source-bound node addresses                  |
| `studio_candidate_evaluate` | Actual complete or partial engine result, morphemes, failures, independent loose-piece results and distinct comparisons |
| `studio_candidate_propose`  | Evaluated hypothesis for human review, rationale, uncertainties and optional many-to-many source/node alignments        |
| `studio_evidence`           | Captured registered PDF metadata, and explicitly requested crop pixels through the managed evidence service             |
| `studio_question`           | Focused question, optionally tied to a candidate/node revision                                                          |

Dictionary row indexes are the ones from the embedded website gzip; they are never treated as SQLite IDs. Verbal engine IDs are separate. Conversion delegates to the existing `dictionary_predicate` implementation, preserving full definitions and exact verb sense/class checks. Every dictionary insertion records its dataset identity and selected sense, including nonverbal predicates. Direct constructor/raw creation is a hypothesis and cannot manufacture dictionary evidence.

When a candidate evaluates completely, include `translation: {text: "tentative Portuguese translation", uncertainties: []}` in `studio_candidate_propose`, including for a single noun. Translate the whole actual evaluated output using lexical meanings and explicit subject/object roles. This is part of the same run. Missing translation returns `TRANSLATION_REQUIRED`; partial failed main expressions can be proposed without translation. Editing or reevaluating clears the earlier translation, and proposal retrieval exposes its exact revision/output binding. These translations never automatically overwrite human draft text.

Raw source is limited to 100,000 characters per piece; forest limits are exactly those in `src/domain/canvas.ts`. Tool payloads stay below the worker's 1 MiB request boundary. Search pages contain at most 40 results. The small fixed tool-schema catalog is returned completely on the first discovery page: Codex0.153.4 does not import later pages, which previously hid evaluation and proposal tools. Large candidate responses return an explicit compact receipt after the complete candidate is committed. Inspect them with `studio_candidate_get` using `view:'source'`, paginated `view:'nodes'`, `nodeId` for exact node code, or `view:'evaluation'`; omitted details are not silently presented as absent.

## Builder parity inventory

`electron/authoring/shared-entry.ts` imports the same source modules as the contributor canvas. `electron/shared-authoring.cjs` bundles that import graph without a second DSL generator. The authoritative Python parser supplies exact AST spans; morphology and evaluation remain in the selected engine.

| Contributor action                                  | Headless equivalent                           | Shared implementation                                                          |
| --------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------ |
| Insert piece / loose piece                          | `add`, `predicate`, `dictionary`, `reuse`     | `editCanvas`; existing Python constructor/dictionary/resolver                  |
| Replace source or repair unsupported source         | `raw`, `replace`                              | `editCanvas` source guards; exact raw remains recoverable                      |
| Detach, duplicate, remove                           | `detach`, `duplicate`, `remove`               | `editCanvas`, including explicit holes                                         |
| Connect/move into a hole, swap operands             | `connect`, `swap`                             | `editCanvas`, rejecting overlapping ancestor scopes                            |
| Combine independent roots, choose order             | `combine`                                     | `editCanvas` supported binary operations                                       |
| Set result/main piece                               | `make-main`                                   | `editCanvas`, moving the previous main into loose pieces                       |
| Position and orientation                            | `position`, `layout`                          | Validated canvas state; geometry never changes realization                     |
| Chain operation on either side                      | `operation`                                   | `addTreeOperation` and Portuguese operation terms                              |
| Change a binary operator or swap its sides          | `operator`                                    | `changeTreeOperator`, preserving source comments                               |
| Edit inline `.var(1)` / scalar call arguments       | `argument`                                    | `editInlineArgument`, decimal comma and exact string quoting                   |
| Remove an operation retaining a chosen child        | `replace` with the inspected child's code     | Same guarded scope replacement as the tree inspector                           |
| Expand a verified reused compound                   | `reuse` / `replace` after verified resolution | Existing destination binding/equivalence checks                                |
| Occurrence definition wrapper                       | Bounded raw/replace of `studio_define(...)`   | Existing parser/interpreter; exact definition survives later human publication |
| Undo/redo, human acceptance                         | Owner/human draft workflow                    | Not delegated to model tools; competing scratch branches remain available      |
| Pan/zoom/collapse/search/highlight/fullscreen       | UI presentation                               | No source operation or tool is necessary                                       |
| Source/lexicon publication or ground-truth approval | Human review only                             | Explicitly absent from the MCP allowlist                                       |

An address is `{nodeId, expectedRaw, fragmentId?}`. `expectedRaw` is the full current source of that container, not just the displayed node code. The candidate revision guards the forest; exact spans guard each occurrence. A previous revision or raw mismatch is an error, not an instruction to overwrite the current candidate. No engine failure discards successful independent pieces.

## Example authoring sequence

1. Read `studio_guide` and `studio_context`; inspect preserved text, uncertainty and reviewed context.
2. Search `studio_dictionary_search({query:'abá'})`, then retrieve the chosen `entryIndex`/`datasetFingerprint` with `studio_dictionary_entry`.
3. Create `studio_candidate_create({})`.
4. Apply `studio_candidate_edit({candidateId,expectedRevision,action:{type:'dictionary',entryIndex,datasetFingerprint,constructor:'Noun'}})`. Retain the returned revision.
5. Inspect the candidate, add another piece, connect/combine it using current addresses, and evaluate with `studio_candidate_evaluate`.
6. Inspect annotations/morphemes, intermediate failures and differences in original spelling. Exact, spacing/case-insensitive and accent-insensitive equality are separate fields. None establish grammar or editorial status.
7. Propose a candidate with a concise evidence-based explanation and explicit uncertainties, or use `studio_question`. Feedback belongs to a later input revision and may preserve alternatives.
8. The contributor previews it, explicitly uses it in their draft, then enters the existing combined passage-plus-lexicon review. Ground truth remains its separate decision.

Do not flatten an opaque transcription into a literal predicate merely to obtain the desired surface. Operators alone do not prove subject/object roles. No certainty percentage, private reasoning trace or automatic approval is stored by these tools.

## Reconstruction and permitted evidence

The frozen `manifest.dictionary.fingerprint` is checked on every dictionary search, exact lookup and conversion. A changed dataset requires a fresh submitted input.

The captured manifest may supply `mode:'reconstruction'`, `excludePassageIds`, `excludeConstructionIds`, `excludeLexicalNames` and `allowedSourceIds`. Reconstruction withholds the target passage's expression, canvas and selected node. Search and resolution both enforce exclusions: a merged reusable structure is conservatively withheld if any recorded occurrence came from an excluded answer, even when other occurrences also exist. Named lexical answer references cannot enter a saved candidate. Unrestricted helper inspection is unavailable in reconstruction because helper bodies can disclose answer-derived structures.

The manifest is an input to the owner, not a tool argument. A model cannot relax its restrictions. Dictionary evidence and reviewed preceding context stay available where permitted. Failed or ambiguous comparisons remain visible; no string match supplies an editorial label.

## Persistence and failure behavior

Every successful candidate update goes through the owner store with an expected revision and operation ID. Ordinary MCP request IDs are scoped to their connection; concurrent clients can independently start their numbering at one. Reusing a request ID with different arguments on the same connection is rejected. For an intentional retry across reconnects within the same attempt, supply a stable, unique command ID in `tools/call` parameters as `_meta: {"studio/operationId": "<command UUID>"}`. Repeating that command reuses its committed result; changing its tool or arguments is a conflict. Without this explicit command ID, inspect the latest candidate before retrying an interrupted mutation. An interrupted external process cannot bypass the current candidate revision by reconnecting.

On cancellation, new calls are blocked, active controllers abort, and late results cannot become successful tool replies. Already committed candidates remain available in the owner store. On profile restart, old scoped credentials do not regain access; the owner must reconcile the recorded job and issue a fresh supported attempt. This does not promise exactly-once provider billing across an ambiguous crash.

An external retry waits for a new question or a newly proposed candidate revision from that attempt. Retained questions and proposals from its interrupted attempt remain readable without immediately completing the new connection.

Structured tool failures distinguish malformed parameters, stale source/engine/candidate, withheld references, dictionary choices, unavailable jobs and engine failures. Invalid raw syntax stays as a repairable source representation. The tools never apply a source patch as error recovery.

## Verification

- `node --test electron/tests/scratch-service.test.cjs`: real Python AST plus shared TypeScript transforms; stale revisions/raw, holes/orphans, scalar arguments, raw repair, nonverbal sense evidence, proposed-hypothesis isolation and comparisons.
- `node --test electron/tests/studio-mcp.test.cjs`: spawned external stdio clients perform initialization/discovery/resources/authentication/revocation/cancellation/repeated IDs; real local Navarro selection, scratch editing, actual evaluation and reuse resolution. The original source, lexicon and reference hashes remain unchanged.
- `node --test electron/tests/analysis-external.test.cjs`: external completion waits for its MCP reply, records no inference, and distinguishes focused questions, timeout and cancellation.
- `python3 -B -m unittest python/tests/test_scoped_authoring.py -v`: website pagination, full sense identity/checksum and conservative reconstruction exclusions.

The MCP tests require permission to bind a temporary local Unix socket. These tests spend no provider usage. The real-data test reads installed dependencies and skips explicitly if they are absent; that is distinct from a linguistic live-provider evaluation.
