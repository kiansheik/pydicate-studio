# Named predicates at publication

New dictionary/manual pieces remain self-contained in a local draft. When the contributor reviews a new passage or an edited expression, Studio extracts literal primitive constructor leaves into `historic/lexicon.tu.py` and substitutes their names in that expression. Existing unsaved drafts use the same path. Unchanged historical expressions and unused loose pieces are not automatically refactored or published.

The read-only planner runs in the actual source namespace and selected engine. It preserves constructor arguments, full definitions, verb IDs/classes, ordering, operations, comments and Unicode. A literal `studio_define(ProperNoun(...), definition)` becomes a declaration plus an explicit definition assignment, because the engine ignores that constructor argument. Source-dependent helper expressions and dynamic constructor arguments remain explicit code. Literal constructors whose shared meaning cannot be proved are rejected with a diagnostic rather than silently inlined.

Names come from normalized headwords: e.g. `abaregûasu` becomes `abareguasu`. Python keywords/leading digits receive a prefix. Occupied names include engine/shared bindings and all historic source identifiers, including future declarations. A collision adds a stable lexical-identity hash, extending it if necessary. Spelling alone is never identity: class, complete predicate state and realization/annotations must match. Exact shared equivalents are reused only when their binding also matches in the destination namespace. Repeated identical leaves share one declaration. Isolated nonrealizing leaves compare their exact state and failure outcome; a pre-existing whole-expression failure remains visible.

The ordinary review opens with the current draft result (only for the matching passage/revision), word headwords and concise meanings, and human before/after fields. Long definitions and field contents expand separately. **Mostrar diff técnico** reveals exact variable names, diagnostics, paths and both complete file diffs. Recovery and lexical-only edits have their own summaries and never borrow an unrelated current passage result. `preview.diff` remains a combined diff for compatibility, while `preview.files` carries each path, before fingerprint and diff. Previewing performs no source writes. Applying uses the stored reviewed bytes, never newly generated declarations, and rejects if either file changed.

Application stages all replacements and original-byte backups, durably journals every member, writes shared declarations before their dependent passage, and rolls completed writes back if a later write fails. Filesystem renames are individually atomic; the set is not a filesystem transaction. A process interruption can leave a known before/after mixture, recoverable from the journal without overwriting unrelated edits. Recovery restores the passage before removing lexical declarations. One externally changed member blocks recovery of the whole set. Earlier single-file source/reference recovery records remain supported; malformed records produce diagnostics without hiding valid records.

The saved draft adopts the published named expression. The existing source-review approval remains the only application confirmation; ground-truth approval stays separate. Routine tests use disposable corpus copies and make no AI provider calls.
