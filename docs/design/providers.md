# AI connections and provenance

Studio's desktop main process owns both adapters. The browser preview has no provider connection. `AssistantPanel` exposes provider/model configuration, connection checks, streaming, cancellation, failure messages, retry preparation and separate output history. The four tasks are translation, constituent/morpheme explanation, expression proposals and grammar problem investigation.

## Supported transports and authentication

- **Codex:** the installed `codex app-server --listen stdio://` uses JSONL RPC. Studio initializes each connection, starts an ephemeral thread, starts a turn, consumes `item/agentMessage/delta` and `turn/completed`, and interrupts cancellation. It uses existing Codex-managed authentication (`codex login`). The configured local model remains the default; the model list is discovered from the server. No API key or account identity is sent to the renderer. Threads use a read-only sandbox, shell/app/web tools are disabled, configured MCPs are disabled for that thread, and model-initiated host operations are declined. Studio supplies bounded authoring context itself. [Official App Server documentation](https://learn.chatgpt.com/docs/app-server) and [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) were inspected on 2026-09-16; the installed CLI was `0.153.4` and its generated local schema verified the `read-only` enum.
- **Claude:** Node's main-process `fetch` calls `POST https://api.anthropic.com/v1/messages` with `stream:true`; the SSE decoder handles split UTF-8, errors, completion and truncation. `ANTHROPIC_API_KEY` is read only from the desktop environment. `ANTHROPIC_WORKSPACE_ID` supports keys requiring a workspace selection. Claude Code's login is not reused as an API credential. The model is editable and available models can be discovered through authenticated `GET /v1/models`. [Official streaming documentation](https://platform.claude.com/docs/en/build-with-claude/streaming), [authentication](https://platform.claude.com/docs/en/manage-claude/authentication) and [Messages API](https://platform.claude.com/docs/en/api/messages/create) were inspected before implementation.

No new runtime packages are required. An ordinary desktop launch must inherit the desired credential environment. Key entry is deliberately outside the renderer: configure it in the environment, then launch `npm run desktop`. `PYDICATE_CODEX_BIN` can select the local Codex executable. No secrets are written to source or project configuration.

## Context and explicit human acceptance

Each request carries project ID, stable passage ID, draft revision, source expression/fingerprint, current raw expression, selected constituent, transcription, independent source/human translations, historical target, annotations/evaluation and engine fingerprint. Main-process context adds surroundings, lexical definitions, repository/content versions and durable PDF evidence. Only PDF asset/page/region metadata is sent; the model is told that it has not seen the facsimile image.

The existing `vscodetupy` workflow was inspected at clean HEAD `d9db782`, including `mcp.example.json`, `docs/source-authoring.md` and its agent state/log. Studio reuses `oldtupicorpus`'s actual `authoring.mcp_server` through a fresh subprocess with a read-only tool allowlist. Fresh subprocesses avoid the upstream engine module cache described in the VS Code workflow. `get_source_context` and selected-reference `search_lexicon` calls supply results and explicit upstream failure diagnostics. The allowlist also identifies `render_candidate` and `search_rendered_expressions` for further host-driven context requests; this version does not grant the model an autonomous tool loop. Studio's selected-draft evaluation comes from its authoring runtime and remains separate from the upstream MCP's full-source rendering.

Requests and returned text are persisted separately under the desktop state's `ai/` directory, hashed by project/passage/request identity. Each record includes original input, SHA-256 input digest, provider, actual model when returned, timestamps, status, original AI text, structured suggestion and human acceptance events. Atomic partial checkpoints permit recovery after an interrupted request; terminal writes are serialized after partial writes. A restarted unfinished request is shown as failed/interrupted and can be retried with a new ID. Corrupt history is surfaced without replacing it.

Request records also retain the exact progress phases and their times: local source context, authoring MCP, provider connection, conversation startup, submission, accepted/waiting, reasoning activity, text streaming, reconnection and terminal status. The UI displays elapsed time and the age of the last received activity. It rereads local history while active to recover missed events; this never starts or polls a model generation. Raw model reasoning is neither stored nor displayed. Cancellation races each awaited operation, reaches MCP/Codex startup, and prevents any later context result from starting generation. For an accepted Codex turn the host sends `turn/interrupt` and allows up to two seconds for acknowledgement before closing its child.

An inactive startup phase fails after 35–45 seconds (local context: 45, MCP: 40); accepted generation fails after 90 seconds without activity. The total request limit remains 180 seconds. Failures identify the last phase, preserve partial output and never automatically retry. Empty provider completion is reported as failure rather than an empty successful translation. Older version-1 histories remain readable without rewriting them.

Codex reasoning effort is now an explicit, persistent Studio choice, defaulting to `medium`, independent of global Codex settings. Model discovery exposes the supported effort choices; Studio sends the requested choice on the thread and turn and records it with the result. The selected model is preserved. Reasoning/item notifications are used only to report activity, and completed message items recover text when a transport omits deltas. These fields and notifications were checked against the installed generated schema and [official App Server documentation](https://learn.chatgpt.com/docs/app-server) on 2026-09-17.

The UI ignores wrong-passage events, never replaces terminal output with delayed partials, and disables acceptance into a different draft revision. A translation is first previewed and may be edited before an explicit human acceptance into the draft. Expression proposals have a current/candidate preview and go back through the normal parse/evaluation flow. Grammar investigations remain proposed explanations/rationale/regressions, with no automatic engine repair. Every AI record keeps `editorialApproval: null`; historical targets and authoritative approvals are untouched.

## Verification and current external blocker

Run the deterministic provider contracts with `node --test electron/tests/providers.test.cjs`; domain revision/late-event checks live in `src/domain/ai.test.ts`. These are explicitly fake transport fixtures, not evidence of a connection.

`npx playwright test tests/providers-progress.spec.ts` checks the actual assistant component using a simulated local bridge: distinct phases, elapsed status, medium default, cancellation and no automatic retry. Ordinary `check`, desktop/browser suites and native smoke commands do not run the usage-consuming provider smoke.

`node scripts/provider-smoke.cjs docs/design/provider-authenticated-check.json` is an explicit real, authenticated check. It sends one short linguistic prompt to each configured provider, writes a credential-free report, and persists/reloads its results in a temporary Studio state directory. It neither reads nor writes the historical corpus. Running this smoke consumes provider usage.

The recorded check on 2026-09-17 UTC (2026-09-16 local) confirmed:

- Codex recognized the local ChatGPT authentication, returned its real model catalog, and completed a streamed response with the locally configured `gpt-6-astra`. The response and request provenance were persisted and reread.
- Claude authenticated successfully for the actual model catalog. Real message generation failed with HTTP 400. A focused second request established the provider's exact error: **"Your credit balance is too low to access the Anthropic API. Please go to Plans & Billing to upgrade or purchase credits."** The adapter is implemented and contract-tested; a Claude generated response is **not verified** until that external account billing blocker is resolved.
- The restricted command sandbox blocked initial CLI state access and network access; the real checks were run with approved execution outside that sandbox. This is separate from Studio's model thread read-only sandbox.
- The real local authoring MCP successfully answered `get_source_context` for Araújo ordinal 67 and `search_lexicon` for `apiti` in a fresh process with the selected engine import paths. This verifies read-context reuse independently from the provider smoke.

See [the raw check report](provider-authenticated-check.json). The smoke is not evidence of linguistic adequacy across Araújo, a PDF-image vision workflow, or an automatic grammar-repair workflow.

## User-reported stall, 2026-09-17

The user's persisted first-line Codex request had completed local/MCP context, produced zero output characters and failed at the 180-second limit. The old UI still said it was obtaining context because every empty response used the same placeholder. The old request did not record provider phases, so its precise model-side stall cannot be established retrospectively. The local Codex configuration had `model_reasoning_effort="ultra"`; silently inheriting that setting is a plausible latency contributor, not a proven explanation of this particular timeout.

The repair was checked without another generation request: the actual first-line `get_source_context` completed successfully in 388 ms; Codex authentication/model discovery completed in 735 ms and advertised `medium` as the selected Terra model's default. The real old request remained readable through the new validator in a temporary copy, and the original bytes stayed unchanged. Regression coverage includes ignored-signal transports, cancellation during source/MCP/CLI initialization, graceful turn interruption, late output, persisted progress, explicit reasoning choice and completed-item fallback. A new linguistic generation was intentionally not run and is not claimed as verified.
