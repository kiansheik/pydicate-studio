# Python service

Python 3.10+ and Git are required for the developer desktop. The worker and the verified `apiti` engine path use the standard library; it imports the selected local engine's `pydicate`/`tupi` modules and their data. A bundled runtime and distributable clean dependency lock are later packaging work.

Run focused checks with `python3 -B -m unittest discover -s python/tests -v`. Start the service with `python3 -B python/worker.py --state-dir /a/studio-owned/state/folder`. The desktop sets that folder automatically under its application data directory.

The protocol is one JSON object per line on stdin/stdout: `{ "id": 1, "method": "open_project", "params": { "parentPath": "/path/containing/both/clones" } }`. The only methods are `open_project`, `refresh_project` (empty params), and `render` (the exact `RenderRequest` in `src/domain/types.ts`). Results are `{id,result}`; failures are `{id,error:{message,code}}`. Rendering accepts a validated structured `apiti / nde / moro` analysis, never Python source supplied by the UI. Each render imports the known engine API in a fresh child process and checks content fingerprints before and afterward.

Source loading uses the Python AST and original text. It reads historic top-level list items and `+=` additions, preserves unfamiliar expressions, and does not import a corpus module, regenerate records, or write either neighboring repository. Stored surfaces are legacy references matched by the existing ordinal convention, not new editorial approvals. Broken source files become diagnostics while other documents stay readable. Source files are never rewritten; byte-preserving source export/editing is not implemented.

UUID identities are stored only in Studio's sidecar. Unique unchanged expressions retain IDs after movement or insertion. External expression rewrites receive new IDs; earlier IDs remain in the registry so a draft cannot silently attach to changed source. Repeated identical expressions are scoped to the source content version. This conservative local policy is not the durable corpus identity/review-event schema migration required for collaboration. Without `--state-dir`, IDs are explicitly provisional content fingerprints.

Repository fingerprints hash HEAD and relevant tracked/nonignored untracked file contents: engine `pydicate/`, `tupi/`; corpus `historic/`, `authoring/`, `ground_truth/records/historic/`. Deleted tracked files affect the hash; bytecode caches are excluded. Repository-wide dirty state is reported separately. The combined realization fingerprint also covers Python runtime identity and the Studio adapter implementation. A render requires the project fingerprint from its current load, so changed engine or corpus contents require a refresh. These checks are change detection, not a sandbox for untrusted engine repositories.

To refresh the observed local compatibility record and the eight actual-engine example snapshots deliberately, run `python3 -B python/snapshot.py --parent /path/containing/both/clones` from the Studio root. The default output files are `src/domain/render-snapshots.json` and `docs/design/compatibility.local.json`. Their scope is this authoring slice; they do not establish that the whole corpus imports or that clean published HEADs reproduce a dirty local environment.
